A closed entry, an archived working, a dated report: each says what was true on
its date, and that is what it is for. A check asking whether the code still
matches is asking a different question, and where it fails the run, the
cheapest way to make it pass is to edit the record.

**That edit is silent and it is not tidying.** A closed entry diagnoses a
function that built a dense table; the entry's own work replaced it with
something else, and the class it named is now the replacement's. Repointing the
path to where the class lives now leaves a green check over a sentence that is
false about today's code, in the strongest form the record has - and nothing
downstream can tell, because a citation is checked for resolving and never for
being true.

**So report it.** The run says which dated records the code has moved under and
does not fail; the reader repoints where the sentence survives the move, and
writes the name as ordinary prose where it does not. The listing is worked down
rather than lived with, because one that never empties is one nobody reads -
the same demand [[1T]] makes of a proxy and the finished-not-moved listing makes
of a closed entry. The listing `kb check` ends with, of closed entries the code
has moved under, is where this record does it.

**The line is what a reader is sent to.** An `outcome` is evidence somebody is
meant to reach and `kb.py stale` runs it, so it fails wherever it stands. The
prose around it is history. Which side a thing is on is decided by whether it
is read for what is true now, not by how strong its form looks - the same
division [[1P]] draws between a document describing behaviour and a record of a
day.
