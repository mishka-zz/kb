The document already said it: prefer a reference with no error bar, and land an
exact gate before a fitted one for every new capability. It even named the
outstanding candidate. The suite drifted anyway, and every gate it drifted with
was written after the principle.

**Nothing was disobeyed and nothing was forgotten.** Each gate was built for a
capability, each reached for the reference nearest to hand, and no single step
looked like the wrong one. What was missing is that no run and no check ever
asked the question the principle asks, so the drift was invisible in exactly the
place it was accumulating.

The lesson is about where a rule has to live rather than about anybody's
diligence: a principle that is only prose is checked when somebody reads the
prose, which is at the moment a document is written and not at the moment work
is done. What made it stick was writing the classification into the run itself -
each gate declaring whether its reference is exact or fitted, held to it by a
test - so a new gate cannot join the suite without answering the question.

That is the same shape as every other stored-answer failure: what is written
down goes stale, and what is computed cannot.
